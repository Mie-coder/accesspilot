# AccessPilot 14 天学习与开发计划

> 你负责亲手编写核心业务逻辑、解释原理和提交 Git；辅导 Agent 负责补充自动化测试、运行质量检查、查资料、审查代码和协助调试，不能悄悄替你实现整个业务功能。

**目标：** 每天投入 4–6 小时，用 14 个学习日完成一个可部署、能在面试中独立讲解的企业系统访问申请 Agent。

**架构：** React + Vite 展示业务流程；FastAPI 管理业务状态；LangGraph 编排申请助手和只读风险审查 Agent；PostgreSQL + pgvector 保存业务数据与政策向量；DeepSeek 负责对话和工具调用；百炼负责政策文本向量化。

**技术栈：** Python 3.11、FastAPI、Pydantic、pytest、SQLAlchemy、PostgreSQL、pgvector、LangChain、LangGraph、React、TypeScript、Vite、Vitest、Docker Compose、Nginx。

## 学习与勾选规则

每个功能都遵循：辅导 Agent 先说明业务目标并准备测试 → 你亲手写最小业务实现 → 辅导 Agent 运行并修正测试/规范问题 → 你用自己的话解释三句话 → 提交 Git。

- 只有你提供测试输出、运行结果或代码证据后，辅导 Agent 才能将检查点从 `[ ]` 改为 `[x]`。
- 每次开始辅导前，Agent 必须先读取本文件，说明当前学习日、已完成项和下一项。
- 某天没完成就顺延，不跳过未完成检查点。

## 其他 Agent 的安全用法

- **资料 Agent：** 只查官方文档并附来源。
- **教学 Agent：** 解释一个概念，然后用问题检查你的理解。
- **测试 Agent：** 提出边界场景，由你选择并亲手写测试。
- **审查 Agent：** 读取 Git diff，按文件和行号报告问题，不直接编辑。
- **调试 Agent：** 从报错提出可验证假设，让你逐项验证。

不要让其他 Agent 自动完成一整天、替你提交代码、虚构测试结果，或生成你无法在面试中解释的实现。
