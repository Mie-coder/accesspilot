# AccessPilot v1.2 产品说明书（精简版）

**状态：** T18–T25 产品与证据产物已完成；`product_verified=true`，`interview_ready=pending_user_verification`；不推送、合并或部署
**更新时间：** 2026-08-12
**已验证基线：** AccessPilot v1.1，本地提交 `c683d84`
**Canonical Spec：** `docs/specs/accesspilot-productized-agent-v1.2.md`
**Ticket 列表：** `docs/tickets/accesspilot-productized-agent-v1.2.md`
**版本主题：** 能理解上下文续答，能通过独立账号完成可信的多角色权限申请闭环

## 0. 本轮范围决定

用户基于 v1.1 实际体验，将 v1.2 从“完整企业权限生命周期”收窄为以下五项：

1. **先修上下文意图识别。** 当系统刚询问申请期限时，用户输入 `111` 应被理解为 111 天并接受目录校验，而不是落入固定帮助回复。
2. **增加独立登录界面。** 四个虚构账号通过登录建立各自服务端 Session；产品内不再用角色下拉框直接改变身份。
3. **用登录账号走通同一申请。** 申请人、直属经理、数据负责人、权限管理员在独立浏览器或重新登录后处理同一个 Case。
4. **保留一层可讲清的 AI 深度。** Decision Packet 区分已验证事实、政策依据、申请人说明和 AI/规则建议；模型只做受约束建议，不做审批和开通。
5. **延期重型能力。** 到期回收、复杂预算账本、多 Attempt 恢复、Evidence Lab、完整多租户平台和 168 小时能力认证不进入 v1.2。

此前 DeepSeek 评审针对的是已扩张的旧版 v1.2。它仍作为历史记录保留，但与本轮精简决定冲突的部分已被本节取代，不能据此把延期范围重新带回 v1.2。

## 1. 为什么做这个版本

### 1.1 v1.1 已经有的能力

- 对话收集权限、期限和业务理由；
- 权限目录解析与政策 RAG；
- 经理→数据负责人串行审批；
- 模拟 IAM 幂等开通与未知结果恢复；
- 申请时间线、SSE、安全事件和固定评测。

### 1.2 这次只修三个决定性问题

1. **上下文断裂。** 当前路由只把“111 天”识别为申请续答，纯 `111` 会被归为 `help`，因此很多陌生输入看起来都返回同一句话。
2. **身份仍是演示切换。** Demo 模式允许在 EMP-001～004 之间直接切换，没有真正的登录凭证与独立 Session。
3. **业务事实被 Workspace 困住。** 角色可以在同一 Workspace 内演示，但不同登录会话不能可信地共同处理同一申请，部分动作也缺少资源级角色 ACL。

v1.2 的目标不是伪装成生产 IAM，而是把这三个问题做成一条完整、可验证、可在面试中解释的纵向闭环。

## 2. 产品定位

**一句话定位：**

> AccessPilot v1.2 是一个具备上下文续答、服务端身份和多角色协作边界的企业访问申请 Agent 原型。

它不是：

- 真实 SSO、IAM 或 IGA 平台；
- 通用聊天机器人；
- 可由模型自主批准、开通或改变身份的 Agent；
- 完整多租户或权限生命周期产品。

## 3. 虚构账号与职责

| 账号 | 角色 | 在旗舰场景中的职责 |
|---|---|---|
| `EMP-001` | 申请人 | 发起限时权限申请、查看 Case 和最终开通结果 |
| `EMP-002` | 直属经理 | 处理第一步审批 |
| `EMP-003` | 数据负责人 | 在经理通过后处理第二步审批 |
| `EMP-004` | 权限管理员 | 在全部审批完成后执行模拟 IAM 开通 |

这些账号固定属于同一个虚构 Demo 组织。v1.2 不建设组织模型或跨组织能力；登录页明确标记“作品集 Mock 登录”，不得宣称接入真实企业身份系统。

## 4. 旗舰体验

1. 申请人从独立登录页使用 EMP-001 登录；
2. 在对话中选择权限；系统追问期限时，申请人直接输入 `111`；
3. 系统根据当前待补字段把 `111` 解释为天数，并给出“接受”或“超过该权限期限上限”的具体结果；
4. 申请人补充理由、明确确认并提交；
5. 系统生成可追溯的 Decision Packet；
6. EMP-002 在另一个浏览器登录，处理经理待办；
7. EMP-003 登录，在前序通过后处理数据负责人待办；
8. EMP-004 登录，只在全部审批通过后执行开通；
9. EMP-001 重新登录，看到同一个 Case、审批时间线和 Grant；
10. 演示一次越权访问和一次模型不可用，系统均失败闭合且不伪造成功。

## 5. 上下文意图识别

纯文本本身不总有唯一含义。v1.2 不把所有 `111` 都猜成期限，而是先检查服务端保存的“当前正在等待什么”。

| 当前上下文 | 输入 `111` 的结果 |
|---|---|
| 刚询问申请期限 | 确定性解释为 111 天，再做权限目录期限校验 |
| 正在等待权限名称 | 提示未识别该权限，要求输入名称或编码 |
| 正在等待业务理由 | 提示理由过于模糊，不把数字保存为理由 |
| 申请已完整、等待确认 | 提示必须明确回复“确认提交”或继续修改 |
| 没有活动申请上下文 | 询问“111 是期限、权限编号还是其他内容？” |
| 用户明确问“你能做什么” | 仍进入帮助，不被活动草稿劫持 |

### 5.1 必须满足的行为

- 服务端游标先在 T18 绑定 Workspace、当前 actor、草稿 revision、待补字段和最近一次有效追问，T19 再绑定 AuthSession；
- 只有唯一活动 Cursor 的 `expected_field=duration_days` 时，纯正整数才按天数解析；
- `0`、负数、超长数字或超过目录上限返回字段级错误并继续等待期限；
- 无效上下文不修改草稿、不确认、不调用模型、不消费模型额度；
- 本版本只为纯数字无效上下文返回 `intent=unknown/business_status=needs_clarification`，不承诺重写所有未知短句。

本版本不做代词消解、多主体推理、完整对话摘要或通用模型路由。

## 6. 独立登录与账号切换

### 6.1 登录页

- 提供四个服务端 allowlist 账号的选择式 Mock Login；
- 展示四个虚构账号的角色说明，便于面试演示；
- 登录成功后进入对应角色工作台；
- 切换角色必须退出并重新登录，或使用另一个独立浏览器窗口；
- 产品页面不保留“切换 EMP 身份”的控制台；当前 T19 实现已关闭旧 Demo/匿名 Workspace 入口。

### 6.2 服务端身份

登录成功后，服务端原子创建私有 Workspace 与 AuthSession，并以 HttpOnly Cookie 绑定：

- 员工账号；
- 角色；
- 私有 Workspace；
- 过期与注销状态。

业务接口只信任 Session 派生的 Principal。除登录允许的 `account_id` 外，客户端在 body/query/form/header 中提交的 employee、role、workspace 或 session 身份字段一律稳定拒绝。写接口同时使用 CSRF 与来源校验。

### 6.3 诚实边界

这是 Mock 登录，只证明：

- Session 隔离；
- 服务端身份绑定；
- 角色与资源 ACL；
- 多账号协作。

它不证明真实用户身份、账号凭证安全、OIDC/SAML 集成或生产 Session 平台。

## 7. 共享 Case 与资源权限

- 未提交草稿与聊天仍属于当前 Workspace；
- 正式提交后形成共享 Access Case，不因退出登录或关闭原窗口丢失；
- 申请人只能查看自己的 Case；
- 经理只看到当前分配给自己的步骤；
- 数据负责人只能在经理通过后看到可决策步骤；
- 权限管理员只能处理已全部批准的开通任务；
- 猜测 ID、错角色、自审批、乱序审批和未批准开通均在业务写入或模型/IAM 调用前拒绝；
- v1.2 固定单 Demo 组织，不声明跨组织隔离或多租户能力。

## 8. Decision Packet 与模型边界

每个正式 Case 最多有一份 Decision Packet，包含：

- 申请人、权限、期限和理由的冻结事实；
- 权限目录与政策依据；
- 申请人说明；
- AI 建议或规则建议；
- 风险关注点、未知项、审批路线和版本信息。

每个条目明确标记来源：

| 来源 | 可以做什么 | 不能做什么 |
|---|---|---|
| 已验证事实 | 支撑身份、目录、状态和守卫 | 引用模型猜测 |
| 政策依据 | 支撑解释与人工审批 | 编造未检索到的政策 |
| 申请人说明 | 保留用户陈述 | 自动升级为事实 |
| AI/规则建议 | 汇总风险和提醒未知项 | 批准、拒绝、开通或改变身份 |

DeepSeek 只接收脱敏后的冻结事实和本轮政策证据，并返回严格结构。超时、无 Key 或非法输出时，Packet 明示“AI 建议不可用”，继续使用已验证事实和政策证据，不伪造模型结果。

v1.2 不建设异步 Operation、Tenant 预算桶、多次 Provider Attempt 或生产 Worker。

## 9. 页面与信息架构

1. **登录页：** 选择一个虚构账号并建立独立 Session；
2. **申请工作台：** 对话、草稿、上下文澄清与提交；
3. **我的申请：** 申请人跨登录查看已提交 Case；
4. **审批待办：** 经理与数据负责人只查看当前可处理步骤；
5. **开通任务：** 权限管理员处理已批准申请；
6. **Case 详情：** Decision Packet、审批、开通和审计时间线。

登录页继承现有设计语言，不在本版本启动新的视觉设计系统。

## 10. v1.2 P0 范围

- 服务端上下文游标与纯数字续答；
- 纯数字无效上下文的 `unknown/needs_clarification` 与差异化回复；
- 独立 Mock 登录页、AuthSession、退出、过期、CSRF；
- 四个预置账号与服务端 Principal；
- 正式 Case 跨 Session 重读、私有草稿隔离；
- 资源级 ACL 与越权攻击测试；
- 简化 Decision Packet 和受约束 DeepSeek 建议；
- 经理→数据负责人审批；
- 权限管理员显式开通与既有幂等恢复；
- 四浏览器全流程、固定评测与面试证据包。

## 11. 延期到 v1.3 或更后

- 到期自动回收、回收 Attempt 和人工异常；
- Tenant 预算账本和复杂 Provider 对账；
- Evidence Lab 与产品内故障控制面；
- 完整 Workspace 外键 cutover；
- 通用多租户开户与运营；
- Async Answer Provider、原始 Provider Streaming；
- 生产 Worker、队列、事务外盒；
- 168 小时延迟复测与正式能力认证协议。

## 12. 完成标准

### 12.1 Product Verified

- `111` 在不同上下文产生正确且不同的结果；
- 四个账号拥有独立 Session，产品内不能直接切换 actor；
- 四个浏览器可以围绕同一个 Case 走完申请、两级审批和开通；
- 越权查看、错角色操作、自审批、乱序和身份字段注入失败闭合；
- Decision Packet 明示事实、证据、说明和建议来源；
- DeepSeek 不可用时不伪造结果，流程仍有诚实的人工判断材料；
- 申请人重新登录后可以读取同一 Case 与 Grant；
- 后端、前端、迁移、构建和固定评测通过。

### 12.2 Interview Ready

- 能在 90 秒内说明项目问题、方案和边界；
- 能演示正常路径、`111` 上下文路径、越权拒绝和模型降级；
- 能解释“Mock 登录不等于真实认证”“模型建议不等于审批”；
- 每条简历候选表述能链接到代码、测试、ADR 和运行证据；
- 不需要把完整企业 IAM、回收或生产可靠性包装成已实现能力。

## 13. 交付顺序

1. T18：上下文游标与 `111` 续答；
2. T19：独立 Mock 登录与 AuthSession；
3. T20：共享 Case 与资源 ACL；
4. T21：Decision Packet 与受约束风险建议；
5. T22：跨账号两级审批；
6. T23：权限管理员开通与申请人重读；
7. T24：四浏览器、攻击矩阵与产品验收；
8. T25：ADR、Demo 主线与面试证据包。

每一步都已单独实现、验收并本地提交。T24 判定 `product_verified=true`；T25 只交付面试证据与练习门禁，不替用户证明个人掌握度。

## 14. 非目标与停止点

- 不接入真实企业账号、真实员工数据或真实 IAM；
- 不允许模型决定身份、审批、开通或工具参数；
- 不把 Mock 登录宣传为生产认证；
- 不把 fake provider 全绿宣传为真实 DeepSeek 质量；
- 不实现延期范围；
- T18–T25 产品与证据产物已本地完成；用户本人无稿讲解与迁移题仍待验证；
- 不修改正式简历，不推送、合并或部署。
