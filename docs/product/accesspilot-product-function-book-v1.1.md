# AccessPilot v1.1 产品功能书

**状态：** 产品方向已确认，待按 Tickets 实施
**更新时间：** 2026-08-10
**适用范围：** 使用原创虚构企业数据的作品集演示版

## 1. 产品定位

AccessPilot 是企业权限服务入口，不是只会收集字段的聊天机器人。它通过对话、确定性工具、政策检索和人工审批，帮助员工完成“了解权限—发起申请—审批—开通—追踪”的完整闭环。

本版本追求接近真实企业产品的体验，但不冒充生产身份或 IAM 系统：不接入真实 SSO、组织目录和权限平台，所有员工、权限、政策和审批数据均为原创虚构数据。

## 2. 产品目标

1. 员工不需要理解权限编码，也能用自然语言找到并申请正确权限。
2. 身份、资格、审批、授权和政策结论都来自后端事实源，不由模型猜测。
3. 对话实时展示意图识别、工具执行和回答增量，并保留可恢复业务事件。
4. 普通产品界面不暴露角色模拟、模型额度、故障注入和 Workspace 重置。
5. 作品集能够解释 Agent 编排、RAG、安全守卫、状态机、SSE、评测和成本控制。

## 3. 产品层与 Demo 层

### 3.1 产品模式

- 当前身份由后端会话固定，普通用户不能切换成其他员工。
- 作品集产品模式从服务端配置解析身份，默认绑定 `EMP-001`；浏览器参数、旧 Workspace 演示身份和聊天内容均不能覆盖。
- 顶部只展示当前用户姓名、部门、头像和通知入口。
- 导航按后端职责显示“权限助手、我的申请、我的权限、政策中心、待我审批”。
- 普通用户看不到模型调用次数、Workspace Token、故障模式或重置入口。
- 写操作继续经过确认、权限校验、顺序守卫、幂等和审计。

### 3.2 Demo 模式

Demo 模式仅用于作品集讲解，通过独立且明确标注的“演示控制台”提供：

- 选择预置虚构场景和演示身份；
- 切换申请人、直属经理、数据所有者和管理员；
- 重置 Workspace；
- 模拟 IAM 失败或超时；
- 查看模型调用预算和 Agent 事件；
- 显示“仅用于演示，不代表真实用户可以切换身份”。

Demo 功能开关只决定演示控制台与 Demo API 是否可用；演示会话只在演示者明确选择场景后激活。激活期间产品表面显示清晰的演示场景标识，并提供“返回产品身份”操作。

退出演示会话或关闭 Demo 功能开关时，服务端忽略并清除演示身份覆盖和故障模式，当前身份回到服务端配置的产品身份。原演示身份的草稿、申请和审计事实不删除、不改绑，也不能向当前产品身份暴露。普通产品 API 和所有产品事件负载均不得包含身份控制、故障控制或模型预算字段。

## 4. 用户角色

### 普通员工

查询已有与可申请权限、创建申请、明确确认、查询进度并查看政策依据。

### 审批人

只处理后端分配给自己的审批任务，查看风险与政策证据，不能自审批、越权、乱序或重复审批。

### 权限管理员或安全人员

处理开通失败与状态未知任务、执行恢复、检索审计事件并查看 Agent 质量和成本指标。

### Demo 演示者

只在演示控制台选择虚构场景、切换角色、注入故障和重置数据，不改变真实产品的身份语义。

## 5. 信息架构

```text
员工工作台
├── 权限助手
├── 我的申请
├── 我的权限
└── 政策中心

审批工作台（有审批职责时显示）
├── 待我审批
├── 已处理
└── 申请详情

管理与审计（管理员职责时显示）
├── 开通任务
├── 审计检索
└── Agent 指标

演示控制台（仅 Demo 模式）
├── 演示场景与虚构身份
├── Workspace 重置
├── 故障注入
├── 模型调用预算
└── Agent 事件
```

## 6. 员工侧功能

### 6.1 身份感知

页面从后端读取当前身份。聊天中的其他员工编号不能覆盖身份；旧身份草稿、申请和授权不能在切换后静默转移。作品集只允许从演示场景或演示控制台切换虚构身份。

### 6.2 权限发现

支持“我能申请什么”“我现在有什么”“权限何时过期”等问题。“可申请”来自部门、角色、自助资格和期限规则；“已拥有”只来自当前有效 `AccessGrant`。

### 6.3 权限名称解析

“帮我申请仪表盘查看”应先从当前身份可申请权限生成候选集，再由后端解析器按稳定编码、名称、系统名和受控别名进行规范化精确匹配。受控别名来自随目录版本管理的后端固定映射，只能指向对应权限；v1.1 不提供运行时自由编辑入口。规范化只处理大小写、空白和常见分隔符，不使用无边界模糊匹配。

1. 唯一匹配时写入稳定编码；
2. 多个匹配时把类型化候选绑定到当前草稿的目标权限字段，不新建或修改草稿；
3. 用户选择候选时重新校验身份与资格，权限变化使旧确认失效；
4. 无匹配时说明原因并展示当前可申请权限；
5. 模型不得自行编造权限编码。

### 6.4 多轮草稿、确认与提交

草稿包含权限、期限、业务理由和明确确认，员工身份由后端注入。修改业务字段后旧确认失效；只有明确回复或点击“确认并提交”才创建正式申请。聊天模型不能直接审批或开通权限。

### 6.5 状态与时间线

统一展示草稿、等待确认、已提交、风险审查中、等待直属经理、等待数据所有者、等待开通、开通中、已开通、开通失败、状态未知、已驳回和已过期。每个状态显示时间、责任方和下一步。

## 7. 政策问答

- 基本政策完整列举当前 8 个政策主题；
- 具体问题使用百炼 512 维向量和 pgvector 检索；
- 回答展示政策编号、标题、支持正文和版本；
- 自审批问题引用 `POL-006` 并明确禁止；
- 政策回答使用 `grounded`、`insufficient_evidence`、`retrieval_unavailable` 三种类型化状态；前端据此区分有效依据、证据不足和检索服务不可用。

## 8. 审批、开通与恢复

审批收件箱只返回当前身份可处理的当前步骤，禁止自审批、越权、乱序和重复操作。审批通过不等于权限已开通。

IAM 开通使用稳定幂等键，区分成功、失败和超时未知；状态未知通过查询恢复，不盲目重试；成功后生成可查询的 `AccessGrant`，全过程进入审计时间线。

## 9. Agent 编排

```text
用户消息
→ 后端身份与安全预检
→ 意图路由
→ 权限实体解析
→ 只读工具或草稿提取
→ 业务守卫与状态更新
→ 回答编排
→ 流式事件和回答增量
→ 持久化完成事件
```

只读工具包括员工上下文、可申请权限、有效授权、权限名称解析、政策目录、政策检索和申请状态。身份由服务端注入，SQL、ORM 对象和内部异常不暴露给模型。提交、审批和开通继续由显式业务 API 执行。

## 10. 真实流式响应

当前轮支持：

```text
turn.started
intent.detected
tool.started
tool.completed
draft.updated
message.delta
message.completed
business.status
turn.interrupted
error.recoverable
```

当前轮使用 `POST /api/chat/messages/stream` 返回 `text/event-stream`。模型生成内容使用真实 `message.delta`，不得用前端打字机动画冒充流式；确定性短回答可直接完成。结构化输出通过严格 Schema 前不修改草稿，流结束前只允许一个 `message.completed` 或 `error.recoverable` 终态。

`message.delta` 只服务当前连接，不逐片持久化。`message.completed` 必须包含经过安全检查的完整回答，并在发送完成事件前持久化到对话历史和 Workspace 事件。用户取消时丢弃未完成文本、不生成伪完成消息，保留已经通过业务校验的事实，并持久化 `turn.interrupted`；页面刷新不回放已丢失的 delta，而是恢复完整最终回答或中断状态。

`GET /api/events` 先按 `Last-Event-ID` 回放持久化事件，再保持长连接推送，支持心跳、断开检测和无重复恢复。活动流使用 Workspace SSE，assistant-ui 当前回答使用本轮流式响应；两条流用稳定 `turn_id` 关联。

## 11. 上下文和记忆

线程短期状态保存最近消息、摘要、当前意图、草稿、活动申请和待确认操作。身份、资格、授权、审批和政策始终从 PostgreSQL 与政策库读取。跨会话长期记忆只允许在用户明确同意后保存稳定偏好；本版本不自动学习敏感内容。

## 12. 安全要求

- 拒绝系统提示词、API Key、隐藏推理、内部配置和绕过权限要求；
- 复合攻击指在有效业务请求中同时夹带系统提示词索取、密钥索取、身份覆盖、自审批或工具参数注入；系统保留安全业务意图，但不能泄露内部内容或越过确认、审批、开通和身份守卫；
- 模型输出、草稿、SSE、日志和错误正文执行敏感信息检查；
- Demo 控制 API 与产品 API 分离并受配置开关保护；
- 所有写操作保留审计、幂等和可恢复语义。

## 13. 模型预算与成本体验

“20 次”是 Workspace 模型调用预算，不是聊天轮数。产品界面和普通产品 API 不显示原始预算；演示控制台可以显示已用、上限、剩余和纠错重试消耗。

预算耗尽后，确定性的只读查询、历史回放、草稿查看以及已有完整草稿的“确认并提交”按钮继续可用，不再调用模型。新的自然语言草稿抽取返回明确降级提示，不修改草稿，也不把配额变成负数。

## 14. 质量与运营指标

- 意图识别正确率；
- 权限名称唯一命中率与歧义处理正确率；
- 政策检索召回率和引用正确率；
- 申请一次完成率、平均补问与模型调用次数；
- 首事件、首 token 和完整响应时间；
- SSE 重连重复率；
- 越权、自审批和攻击阻断率；
- IAM 开通与恢复成功率。

指标只来自固定评测或真实测试，不为简历伪造数字。

## 15. v1.1 交付顺序

1. 产品身份与 Demo 控制面分层；
2. 权限名称与编码解析；
3. 真实 SSE 和回答流；
4. 完整政策问答与安全响应；
5. 权限、政策、状态和时间线业务卡片；
6. 产品化评测、指标和作品集证据。

## 16. 非目标

- 真实 SSO、OIDC、LDAP、企业目录或 IAM；
- 允许普通用户切换或冒充真实身份；
- 通用开放式聊天或联网搜索；
- 模型直接审批或开通；
- 自动保存敏感长期记忆；
- 未验证前修改简历或发布指标；
- 未经确认推送、合并或部署。
