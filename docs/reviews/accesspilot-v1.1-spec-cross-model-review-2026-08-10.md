目标、非目标、产品/Demo 身份边界、权限实体解析、双流协议、政策证据、安全守卫、串行 Ticket 和本地提交规则均以 2026-08-10 三份文档为准。本关口没有声称 T12–T17 已有代码或运行证据。

## 3. 评审议题与主控决策

### CR-01 — P1 — 接受

**来源：** Claude，外部标记 P0。

**问题与证据：** 产品功能书 §3、Spec FR-01 和 T12 未定义 Demo 关闭后已切换身份、故障和其他身份草稿的终态。当前 `Workspace` 会持久保留 `actor_id` 与 `fault_mode`。

**主控判断：** 当前仍是实现前规格缺口，尚未造成数据破坏，因此降为 P1；但它直接阻塞 T12 验收。

**决策：** 产品模式由服务端配置身份；Demo 关闭后演示覆盖与故障失效，其他身份业务事实不改绑、不暴露。

### CR-02 — P2 — 接受

**来源：** Claude。

**问题与证据：** T16 把多种状态、可访问性和多个视口压在一条验收中，虽可整体判定，但证据映射不清。

**决策：** 保持每 Ticket 最多 3 条验收，将 T16 AC3 明确为状态矩阵和三档浏览器检查。

### CR-03 — P1 — 接受

**来源：** Claude。

**问题与证据：** Spec 要求 1440×900、1024×768、390×844，原 T12/T16 未完整列出 1024×768。

**决策：** T12 和 T16 显式覆盖三档尺寸。

### CR-04 — P1 — 接受

**来源：** Claude。

**问题与证据：** 当前轮 delta 与 Workspace SSE 分离，但原 Spec 未定义刷新时是否回放 delta、最终回答如何恢复。

**决策：** delta 不逐片持久化；完整 `message.completed` 先持久化再结束。刷新恢复最终回答或中断状态，不伪造 delta 回放。

### CR-05 — P1 — 接受

**来源：** Claude。

**问题与证据：** 原 Spec 只说预算耗尽后允许只读查询，没有定义已有完整草稿的确认和提交，也没有定义新自然语言抽取的降级。

**决策：** 确定性按钮确认与提交继续可用且不调用模型；新自然语言抽取明确拒绝且不修改草稿。

### CR-06 — P1 — 接受

**来源：** Claude。

**问题与证据：** 原政策卡没有区分“没有足够证据”和“检索服务不可用”。

**决策：** 后端类型与前端文案均区分两类失败闭合状态。

### CR-07 — P2 — 接受

**来源：** Claude。

**问题与证据：** 歧义候选与已有草稿、旧确认的交互不明确。

**决策：** 候选绑定当前目标字段但不修改草稿；选择时重新校验资格，权限变化使旧确认失效。

### CR-08 — P2 — 接受

**来源：** Claude。

**问题与证据：** 原 T12 Demo 控制验收包含多个独立控制项，验证证据可能遗漏。

**决策：** T12 分别验证产品表面、Demo 控制能力和关闭 Demo 后的服务端终态。

### CR-09 — P1 — 接受

**来源：** 主控代码核验补充。

**问题与证据：** 当前 `GET /api/model-quota`、聊天返回对象和 `App.tsx` 都直接暴露原始配额。只隐藏右上角数字不能实现产品/Demo 分层。

**决策：** 普通产品响应不返回原始配额和 Demo 控制字段；原始预算只通过受配置保护的 Demo API 提供。

### CR-10 — P1 — 接受

**来源：** DeepSeek 修订后复核，外部标记 P0。

**问题与证据：** “Demo 功能开关”和“当前演示会话”概念混在一起，无法判定功能仍启用时如何退出场景并恢复产品身份。

**决策：** 分离配置开关与 `demo_session_active`；控制台提供明确进入/退出场景，退出或关闭功能都恢复产品身份和清除故障。

### CR-11 — P1 — 接受

**来源：** DeepSeek 修订后复核，外部标记 P0。

**问题与证据：** 原始预算虽已从普通产品 API 排除，但事件契约没有逐字禁止预算字段。

**决策：** 普通产品 API、聊天响应和所有产品事件负载都剥离模型预算字段，只允许受保护 Demo API 返回。

### CR-12 — P1 — 接受

**来源：** DeepSeek 修订后复核。

**问题与证据：** “受控别名”没有定义事实来源和变更边界。

**决策：** 别名来自随权限目录版本管理的后端固定映射，v1.1 不提供运行时自由编辑，未知别名不命中。

### CR-13 — P1 — 接受

**来源：** DeepSeek 修订后复核。

**问题与证据：** 用户取消后半截 delta、业务事实和刷新恢复的关系仍不够明确。

**决策：** 丢弃未完成助手文本、不生成伪完成、不回滚已校验业务事实，持久化 `turn.interrupted` 并在刷新后显示可重试状态。

### CR-14 — P1 — 接受

**来源：** DeepSeek 修订后复核。

**问题与证据：** 政策失败状态未形成后端类型到前端卡片的一一映射。

**决策：** 固定 `grounded`、`insufficient_evidence`、`retrieval_unavailable` 三态，T15 负责产生，T16 负责确定性展示。

### CR-15 — P1 — 接受

**来源：** DeepSeek 修订后复核。

**问题与证据：** “复合攻击”缺少可复现测试定义。

**决策：** 固定申请+提示词、政策+密钥、自审批+身份覆盖、有效意图+未知工具参数四类自动化场景。

### CR-16 — P3 — 拒绝

**来源：** DeepSeek 修订后复核，外部标记 P2。

**问题与证据：** 建议删除 T13 对 T12 的依赖以允许部分并行。

**主控判断：** 个人工作流明确要求稳妥串行，且 T13 候选必须在 T12 固定的产品/Demo 身份语义下验证；该依赖是有意设计，不是阻塞。

**决策：** 保留 T13 对 T10–T12 的依赖。
