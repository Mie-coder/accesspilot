## 1. 匿名化验收包

### 目标

- 用后端类型化事实展示权限的 `eligible`、`owned`、`pending`、`expiring_soon`、`expired` 五种状态。
- 用 `matched`、`ambiguous`、`no_match` 三态展示权限名称解析；候选选择必须回到服务端重新校验，旧确认不能被前端状态直接沿用。
- 用 `grounded`、`insufficient_evidence`、`retrieval_unavailable` 三态展示政策答案，证据不足和检索不可用不得伪造政策正文。
- 用事实 API 和审计事件展示草稿、提交、风险审查、直属经理、数据所有者、开通和恢复时间线，不从聊天自由文本推断授权事实。
- 覆盖加载、空结果、错误、安全拒绝、断线重连、候选键盘操作和三档视口。

### 非目标

- 不接入真实 SSO、企业目录、IAM 或真实政策数据。
- 不在 T16 生成产品化指标、首 token/完成延迟统计或作品集对比；这些属于 T17。
- 不把聊天文本当作权限、政策或申请状态的事实源。
- 不向外部模型发送源码、密钥、私有地址或数据库凭据。

## 3. 内部独立评审与 P1 修复

### T16-IR-01 — P1 — 已修复

候选卡最初存在把展示别名当成事实以及键盘事件可能重复触发选择的问题。修复为候选只使用服务端返回的名称、编码和系统字段，使用原生按钮语义交给浏览器处理 Enter/Space，并增加可访问名称和单次调用回归。

### T16-IR-02 — P1 — 已修复

权限候选选择的重新校验边界过宽，可能把非唯一匹配或不完整资格误报为通过，且旧确认失效标记可能被无条件设置。修复为仅当服务端返回唯一同编码 `matched` 且没有非缺失字段问题时标记 `revalidated`，只有原草稿确实已确认时才返回 `previous_confirmation_invalidated=true`。

### T16-IR-03 — P1 — 已修复

政策回答同时渲染完整目录会重复展示证据；把检索不可用映射为空目录会掩盖真实故障。修复为答案存在时聚焦本轮证据，并保留 `retrieval_unavailable` 的独立状态、提示和重试路径。

### T16-IR-04 — P1 — 已修复

断线和可恢复错误原先只在助手面板可见，用户切到权限、政策或申请页面后无法判断数据是否新鲜。修复为连接状态与当前轮错误解耦，并在业务页面统一显示安全、可重试的状态提示。

### T16-IR-05 — P1 — 已修复

申请时间线可能把当前草稿混入无关正式申请，或在缺少权威开通事实时暗示成功。修复为先按申请人与权限字段判断草稿是否属于同一业务对象；不相关草稿不并入正式申请时间线，时间线只消费类型化详情和审计事件，没有 `access_granted` 时不渲染“已授权”。

### 评审结论

以上 P1 均有针对性回归并在最终测试中关闭。独立前端、后端只读复核未发现残留 P0/P1。唯一非阻塞项是正式构建报告存在大于 500 KB 的 chunk 提示，记录为 P2 性能拆包候选，不影响 T16 功能或安全验收。
