# AccessPilot 产品化 Agent v1.1 Tickets

## 实施规则

按 `T09 → T10 → T11 → T12 → T13 → T14` 串行实施。每张 Ticket 先写可观察行为测试，再实现最小通过改动，由独立只读验证确认验收条件；通过后只创建本地提交，不推送、不合并、不部署。

所有 Tickets 继承 `docs/specs/accesspilot-productized-agent-v1.1.md`、现有设计语言卡和仓库安全边界。

## T09 — 后端绑定演示身份

**状态：** 已完成，已本地验证。

**目标：** 将演示角色从前端参数升级为 Workspace 持有的后端身份上下文，并让申请草稿自动使用该身份。

**验收：**

1. 新 Workspace 默认绑定 `EMP-001`，角色切换后可从后端读取当前虚构员工、部门和角色。
2. 聊天内容和审批请求中的其他 `employee_id`/`actor_id` 不能覆盖后端当前身份或越权操作。
3. 迁移、身份 API、现有申请与审批回归测试全部通过，UI 继续明确标注演示身份。

**主要影响：** Workspace 数据模型与迁移、身份依赖、聊天/审批 API、前端角色切换。

**风险与回滚：** 数据库新增身份字段必须为既有 Workspace 提供安全默认值；回滚时恢复迁移前接口，不删除申请、审批或审计事实。

## T10 — 身份范围内的权限发现工具

**状态：** 已完成，已本地验证。

**目标：** 提供“可申请权限”和“当前有效授权”两个不同的类型化只读工具。

**验收：**

1. `EMP-001` 的可申请权限结果严格匹配目录资格、自助规则和期限，结果包含稳定编码、名称、风险、最长时限和审批策略。
2. 当前有效授权只来自该员工真实 `AccessGrant`，不会混入可申请但未开通的权限或其他 Workspace 数据。
3. 未知身份、空结果和跨身份查询返回稳定错误/空状态，并通过工具与数据库集成测试。

**依赖：** T09。

**主要影响：** 目录工具 Schema、授权查询、工具测试和最小 API 契约。

## T11 — 多意图路由与只读工具执行器

**状态：** 已完成，已本地验证。

**目标：** 在申请字段提取前识别权限发现、已拥有权限、政策问答、申请、状态、安全探测和帮助意图，并只允许调用当前意图的只读工具。

**验收：**

1. 权限/政策咨询不会进入缺字段追问，也不会修改已有草稿；申请意图继续兼容原确认守卫。
2. 路由和工具参数使用严格 Schema，身份由服务端注入；未知工具、越权参数和不合法输出失败闭合。
3. 复合消息可以同时产生安全标记和一个正常业务意图，但不得自动触发提交、审批或开通。

**依赖：** T09、T10。

**主要影响：** Agent 状态、DeepSeek 适配器、意图路由、工具注册/执行、聊天服务和事件 Schema。

## T12 — 政策问答与提示词攻击防护

**状态：** 已确认，待实施。

**目标：** 让用户查看完整政策主题、查询具体政策和自审批规则，并对系统提示词、密钥、隐藏推理和越权要求提供稳定安全响应。

**验收：**

1. 基本政策问题完整返回 8 条政策主题；具体政策回答只引用本轮检索到的政策，检索失败时不编造。
2. 自审批问题明确回答禁止，并引用 `POL-006`；申请、审批和授权状态仍由确定性业务服务决定。
3. 显式提示词/密钥攻击和“正常申请 + 攻击”复合场景均有评测，响应、SSE 事件和日志不泄露内部内容。

**依赖：** T11。

**主要影响：** 政策目录工具、RAG 问答编排、安全守卫、响应证据和固定评测。

## T13 — 权限与政策回答卡片

**状态：** 已确认，待实施。

**目标：** 在现有 assistant-ui 申请台中，用业务卡片呈现后端身份、权限结果、空状态、政策引用和安全提示。

**验收：**

1. 三个快捷问题能触发真实后端能力；权限卡清楚区分“可申请”和“已拥有”。
2. 政策卡展示编号、标题和依据；安全拒绝不显示原始系统提示词或内部异常。
3. 组件测试、可访问性检查、ESLint、TypeScript、生产构建及 1440px/390px 浏览器验证通过。

**依赖：** T11、T12。

**主要影响：** ChatTurn 前端类型、Runtime、ChatThread、结果卡片、事件活动流和现有 CSS。

## T14 — 产品化评测、指标与简历证据

**状态：** 已确认，待实施。

**目标：** 用固定场景证明 V1.1 从单一字段收集器升级为身份感知、多意图、有依据且能抵御显式攻击的权限助手。

**验收：**

1. 新增评测覆盖身份不可覆盖、可申请/已拥有区分、政策完整列举、自审批、草稿隔离、提示词攻击和复合消息，全部通过。
2. 后端/前端全量测试、Ruff、MyPy、Alembic、ESLint、TypeScript 构建和浏览器黄金路径通过，并记录模型调用与关键正确性指标。
3. 形成一份只引用已验证能力的前后对比和简历候选表述；正式简历是否修改由用户单独确认。

**依赖：** T09–T13。

**主要影响：** 固定评测、验收记录、README/架构说明和简历证据草稿，不修改真实简历文件。

## 委派边界

身份迁移、Agent 路由与安全守卫由主 Agent 负责集成。测试补充、只读验收和已稳定接口后的独立前端卡片可以交给范围明确的 `luna_worker`；主 Agent 仍负责审查、回归测试和完成声明。
