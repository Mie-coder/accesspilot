## 3. 时间预算与三条主线

以每个工作日一块 75 分钟深度时间作为试行预算，可在 60–90 分钟内调整。上午或下午哪个窗口稳定就用哪个，不安排两个必须完成的大任务。第一周记录实际可用时间，再校准后续预算。

| 日期或窗口 | 必做内容 | 预算 |
|---|---|---|
| 周一至周六的碎片时间 | 筛选、投递、招聘回复、记录进展；临时面试优先 | 每天 30 分钟 |
| 周一、三、五 | AccessPilot，一个学习单元 | 每次 75 分钟，含 Python 和收尾 |
| 周二、四 | Deep Agents：按现有课程进度完成一个小节或练习 | 每次 75 分钟 |
| 周六 | 招聘反馈、简历口径、Python/后端小题和 Agent 项目模拟讲解；必要时解释过往工程经历 | 60–90 分钟 |
| 周日 | 休息；自愿做简短周复盘 | 0–10 分钟 |

上述基线约每周 10–11 小时，不含真实面试。面试占用原学习窗口，学习单元顺延。第二块空闲时间作为家庭与求职缓冲，不作为进度成立的前提。

保底日：优先处理必要招聘回复，若有精力做 5 分钟口述回忆；家庭事务优先，不将未完成任务叠加成第二天双倍任务。周日无需补投递或补课。

求职按“投递/联系 → 回复 → 约面 → 面试反馈”复盘，不以每日投递数量作为唯一成绩。没回复先检查匹配与简历；面试暴露的问题进入后续学习单元。修正事实错误不等到某个里程碑，正式简历改写仍由用户明确选择后执行。

## 4. 排期：18 个学习单元，约 6 周基础预算

每周 3 个 AccessPilot 单元，18 个单元约 22.5 小时。此预算是学习时间盒，不是“六周必然彻底掌握”的保证。第一单元核对已掌握内容：有证据的部分直接压缩，难点可拆分顺延。

职业目标明确后，这 18 个单元作为首轮学习与诊断框架，不能直接等同“已达到 Python Agent 岗位要求”。从第一周起增加本人编码，必要时将同一主题拆为阅读和独立实现两次；进度顺延，不挤占家庭时间或用理解讲稿代替编码门禁。

前三周是第一轮核心理解和面试准备检查点；不要把第三周写成整个项目全部吃透。后续三周用于执行机制、独立修改和正式演练。保留既有每周节奏，不把阶段编号强绑在具体自然日期上。

### 阶段 A：业务与请求链，单元 1–6，约第 1–2 周

当前自述为没有 Python 基础，因此以下单元先使用相关业务的最小练习，不要求第一次就读懂完整 FastAPI、ORM 或状态图。第一周优先练习“读取一份申请 → 判断缺哪些字段 → 返回结果”，依次学习字典、函数、条件、返回值与基本测试；第二周根据结果补类、类型和异常，再逐步连接 HTTP 接口。每次回到项目核对同一业务行为如何实现。基础仍卡住时顺延后端复杂主题，不以一份 AI 写好的大骨架代替练习。

| 单元 | 唯一主问题 | 定位线索 | 当次可观察产出 |
|---|---|---|---|
| 1 | AccessPilot 服务谁，一份申请如何到达实际授权？ | README、白盒路线、四角色页面 | 当前理解基线；一张本人画的业务流程；区分申请、审批、开通 |
| 2 | 服务端怎么知道“我是谁”，请求怎么到达后端？ | `apps/web/src/api.ts`；`auth.py`；`main.py` | 一次请求的输入、Cookie/身份与响应链；解释为什么聊天不能改角色 |
| 3 | 请求数据如何变成 Python 对象并进入业务层？ | `domain/models.py`；当前接口与 `db/models.py` 中相关对象 | 区分输入校验、业务判断、持久化；独立写一个小校验函数 |
| 4 | 多轮草稿为何知道下一步，修改后为什么重新确认？ | `workspaces.py`；`domain/workflow.py`；`agent/routing.py` | 画一个状态变化；预测无上下文数字和修改后的行为，验证一个分支 |
| 5 | 谁能审批哪张申请，材料为什么需要冻结？ | `decision_packets.py`；`approvals.py` | 解释 Packet、Case 和身份授权；验证一个越序或错角色拒绝场景 |
| 6 | 批准后为什么还需要开通尝试和 Grant？ | `provisioning.py`；`operations.py`；ADR-0002 | 解释批准、成功、失败、结果未知；用已有测试或隔离夹具观察一种故障 |

本表 Python 路径除完整标注外，相对于 `apps/api/src/accesspilot/`。入口只是定位线索，每次先确认实际调用链，不从头阅读所有文件。

阶段检查：能用 5 分钟说明业务和请求主链；能定位其中两个关键行为；不照抄答案写出申请输入校验与一个非法状态拒绝的小函数和测试。若后两项尚不能完成，增加对应 Python 实践单元，不强行进入下一批主题。

## 5. 每次 75 分钟怎么用

1. 5 分钟：回忆上次要点，确认本次业务问题，预测一个行为。
2. 20 分钟：追相关后端或 Agent 代码，同时解释当次遇到的 Python 和业务机制。
3. 30 分钟：本人独立写、改、调试一个最小 Python 行为并验证；从函数逐步到接口、数据读写和工具。可用文档，避免直接照抄模型答案。
4. 15 分钟：复述本次代码数据流、解释必要的取舍与失败边界。不是每次强制讨论全部架构替代方案。
5. 5 分钟：保存真实结果和下次起点，停止本次学习。

Python 提升为核心训练，不再只安排十分钟语法卡。以 AccessPilot 的行为为练习素材，按函数/集合/模块、类型与 Pydantic、类、异常、async、上下文管理器、pytest 顺序补齐必要基础；已有知识不重教。反复卡在某项基础时，用一至两个独立基础练习单元集中补齐，再回项目。前两周的编码时间优先用于小函数和测试，熟练后再进入 FastAPI/数据库；不能一开始就塞进完整框架骨架。

遇到“为什么 response 是这个结构”时，先区分 API 契约与 Python 语法；不要只重复教字典取值。React 只阅读理解接口、状态与事件所需的部分，不安排独立 UI 技巧或组件开发复习；完整架构仍需说清客户端职责。
