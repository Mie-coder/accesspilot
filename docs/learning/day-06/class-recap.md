# Day 6：LangGraph 多轮信息补全课堂总结

## 今天完成了什么

- 正式引入 LangGraph，并在项目依赖中声明。
- 定义 `GraphState`：申请草稿、缺失字段、工具摘要、对话阶段、可恢复错误和下一句追问。
- 实现“每轮只问一个字段”的收集函数与两个图节点：生成下一句追问、接收用户回答后更新草稿并继续追问。
- 实现最小图：`START → 询问节点 → END`。这里的 `END` 表示本轮结束并等待用户回复，不代表申请结束。
- 使用 Checkpoint 模拟服务重启：新图实例能恢复同一段申请对话的状态。

## 业务数据流

1. 新申请创建 `RequestDraft`，生成初始 `GraphState`，阶段为 `COLLECTING`。
2. 询问节点只生成 `next_question`，不猜测或修改用户的申请内容。
3. 用户回答后，回答节点把答案写进新的草稿、重算 `missing_fields`，并继续生成下一句追问。
4. 字段完整时，阶段切换为 `AWAITING_CONFIRMATION`；这不代表审批通过，更不代表 IAM 已开通。
5. Checkpoint 保存 `GraphState`，用户中断或服务重启后可以恢复进度。

## 今天最重要的边界

- 用户没有回答时，节点只能提问，不能替用户填写草稿。
- LangGraph 节点返回“本轮变化的状态字段”；未变化字段不应重复返回。
- `model` 是运行时服务，不放进 `GraphState`；草稿、缺失字段和阶段才是需要保存的对话进度。
- `END` 是一次图执行结束，不是权限申请结束。

## 面试高频问答

### LangGraph 和 LangChain 有什么区别？

LangChain 更像接入模型、Prompt、工具和检索能力的组件层；LangGraph 负责把模型、工具和业务步骤组织成有状态的流程，提供节点、边、暂停和恢复能力。两者可以一起使用。

### 为什么不用一个 `while` 循环？

`while` 循环也能实现多轮对话，但状态保存、分支、等待用户输入、重启恢复和日志追踪都需要手工维护。AccessPilot 有多轮收集、确认、校验、审批和开通等明确边界，用 LangGraph 可以把状态和路径显式化，更容易测试、审计和恢复。

### LangGraph 和 Agent Looping 能一起用吗？

可以。Agent Looping 适合模型理解自然语言、选择工具等灵活任务；LangGraph 适合权限申请这种需要确定状态、流程控制和审计边界的外层编排。模型不能自行决定“已批准”或“已开通”。

### Checkpoint 保存什么？为什么不保存模型？

Checkpoint 保存 `GraphState`，也就是草稿、缺失字段、阶段和下一句问题等对话进度。模型是运行时服务，不是业务状态；恢复时重新提供模型即可。
