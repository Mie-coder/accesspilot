# 我今天终于把 Agent 的“聊天记忆”讲明白了

> 这是 AccessPilot 学习记录 Day 6。不是又接了一个很炫的 AI 功能，而是给权限申请这件小事，补上了“它到底走到哪一步”的记忆。

今天做的是 LangGraph。

一开始听这个名字，很容易以为又是一个“让模型更聪明”的东西。

写到后面才发现，它更像一个流程管理员。

模型负责问人话：

“你要申请什么权限？”

系统负责守规矩：

“你还没说申请多久，所以不能进入下一步。”

而 LangGraph 负责把这两件事按顺序接起来，还记得它们现在进行到哪里。

---

## 一个权限申请，最怕的不是“不会问”，而是“问完忘了”

想象一个用户说：

“我要申请导出客户数据。”

系统其实还缺两件事：申请多久、为什么申请。

最偷懒的写法，是塞进一个 `while` 循环：缺什么就问什么。

它当然能跑。

但用户一关页面、服务一重启，循环没了；系统很可能也忘了：刚才问到第几题、用户已经填了什么、现在应该继续问还是等待确认。

所以今天给它做了一张“进度卡”。

```text
申请草稿：已知什么？
缺失字段：还差什么？
对话阶段：正在收集，还是等待确认？
下一句问题：现在该问什么？
```

这张卡就是 `GraphState`。

它不是权限本身，也不是模型。

它是这段对话此刻的进度。

---

## 把一轮聊天拆成两个很小的动作

以前我会下意识写一个“大函数”：既收回答、又改草稿、又决定下一步、又输出问题。

今天把它拆开了。

第一个节点只做一件事：**问下一句。**

用户还没给新答案，它就没有资格替用户填草稿。它只看当前缺什么，然后生成一句问题。

第二个节点也只做一件事：**收到回答后，更新草稿，再决定是否继续问。**

这个边界看起来有点“啰嗦”，但它避免了一个很危险的幻觉：系统自己把“客户数据导出”填进申请里，然后假装用户说过。

在权限申请里，不能这样。

---

## `END` 不是结束，是“先等你回话”

这是今天最容易误会的地方。

图里有一段很短的路径：

```text
开始 → 生成下一句问题 → END
```

这里的 `END` 不是“申请结束”。

它只是说：这轮程序先停在这里，问题已经展示给用户了；下一步必须等用户真的回答。

就像客服问完“请告诉我申请天数”，然后不会自己替你回答“7 天”。

它暂停，是为了尊重人，也为了让状态可以被保存。

---

## 终于理解了：为什么要用 LangGraph

`while` 循环能不能做？能。

Agent Looping 能不能做？也能。

但它们不是不能追踪，而是“追踪、保存、恢复、分支”都需要自己一点点补。

而 AccessPilot 后面还会有：收集资料、等待确认、校验、审批、IAM 开通。

这些步骤不能只靠模型凭感觉往下走。

LangGraph 把每个步骤变成节点，把下一步变成边，把对话进度变成可保存的状态。

模型仍然可以很灵活：理解用户说的话、把字段名变成自然的问题。

但它不能越过业务边界，自己宣布“权限已经开通”。

这就是我现在对 Agent 的一个小理解：

> 让模型负责不确定的理解，让系统负责不能出错的边界。

---

## 今天落地了什么

- 用 `GraphState` 保存申请草稿、缺失字段、对话阶段和下一句问题。
- 每次只追问一个缺失字段，方便验证和恢复。
- 用户回答后才更新草稿；字段齐全后进入“等待确认”，不等于审批通过。
- 用 Checkpoint 模拟服务重启：新图实例可以读回同一段申请对话的进度。

今天不是把一个 Agent 做得更会说话。

是让它在说话之外，开始记得自己正在做什么、为什么不能越过下一步。

下一步，会把旧的权限校验工具迁到新的草稿契约上，再继续扩展真实模型和确认守卫。
